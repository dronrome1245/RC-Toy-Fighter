# Нейросеть: начни отсюда

Этот файл — обязательная точка входа для любой нейросети в любом новом чате.

## 1. Что это за проект

Взрослый вместе с ребёнком 6 лет превращает пенопластовый самолёт-запускалку 35 см в радиоуправляемую микромодель.

Цели проекта:

1. получить работоспособную RC-модель;
2. научить ребёнка постепенно участвовать в техническом проекте и пилотировании;
3. показать полный цикл проекта: планирование → закупка → сборка → проверка → исправление → завершение.

**Репозиторий предназначен прежде всего для взрослого.** Техническая документация должна быть точной, компактной и удобной для работы. Ребёнок не обязан читать файлы.

Для ребёнка создаются только отдельные визуальные материалы и практические задания там, где это полезно.

## 2. Базовый самолёт

Заказан конкретный донор:

**«Запускалка самолёт пенопластовый 35 см, зелёный»**

Ozon product id: `5530158944`.

Проект разрабатывается именно под фактический экземпляр.

Предыдущая конфигурация для планера около 68 см (`2204 / ESC 20 A / LiPo 2S 450–550 mAh / 5030`) отменена.

До получения, взвешивания и измерения самолёта окончательная электроника не утверждается.

## 3. Что прочитать перед работой

В каждом новом чате читать в таком порядке:

1. `00_AI_START_HERE.md`;
2. `STATUS.md` — единственный источник текущего состояния;
3. `00_РУКОВОДСТВО_ДЛЯ_ВЗРОСЛОГО.md` — рабочий процесс проекта;
4. `DECISIONS.md` — принятые и отменённые решения;
5. `HISTORY.md` — фактически выполненные действия;
6. `SOURCES.md` — исходные данные и внешние источники;
7. `AGENTS.md` — постоянные правила;
8. профильные файлы конкретной задачи.

Если эти файлы недоступны, нельзя восстанавливать состояние проекта по догадке.

## 4. Иерархия истины

При противоречии:

1. последнее явное решение пользователя;
2. `STATUS.md`;
3. более поздняя запись в `DECISIONS.md`;
4. актуальный профильный файл;
5. старые расчёты и исторические материалы.

Отменённые решения не удаляются. Они остаются в истории с пометкой `ЗАМЕНЕНО`.

## 5. После каждого существенного шага

Нейросеть обязана до завершения ответа проверить необходимость обновления:

- `STATUS.md` — изменился этап, следующий шаг, блокировка или перечень актуальных действий;
- `DECISIONS.md` — принято/отменено решение;
- `HISTORY.md` — выполнено действие, заказ, измерение, тест или доработка;
- `SOURCES.md` — появился новый источник, товар, инструкция или фактическое измерение.

Нельзя писать «зафиксировано», если запись в репозиторий не выполнена при наличии доступа.

## 6. Технические правила

Любое существенное техническое решение должно отвечать на вопросы:

1. что выбрали;
2. почему;
3. какие данные подтверждают выбор;
4. какие ограничения остаются;
5. что нужно проверить физически;
6. что это меняет в следующем шаге.

Для конкретных покупок проверять как минимум:

- массу;
- размеры;
- напряжение;
- ток;
- разъёмы;
- совместимость;
- влияние на центр тяжести;
- возможность физического монтажа.

## 7. Работа с ребёнком

Не требуется упрощать каждый технический файл до уровня ребёнка.

В каждом крупном практическом этапе желательно выделить ребёнку одно безопасное действие, например:

- взвесить деталь;
- помочь измерить;
- посчитать комплектующие;
- выбрать из двух вариантов;
- предсказать результат испытания;
- проверить движение руля по картинке;
- отметить завершённый этап.

Объяснение ребёнку даёт взрослый устно. Визуальные материалы хранятся отдельно в `08_Картинки_для_понимания/`.

## 8. Главный принцип текущего этапа

Работаем от реального самолёта:

`получили → сфотографировали → взвесили → измерили → проверили планирование → определили допустимую массу RC-комплекта → выбрали схему управления → выбрали конкретную электронику → закупили → собрали → испытали`.
